# ShivaCore M1.2 — VMM Implementation Baseline

**Specification:** `SC-SPEC-001-REV2.1-M1.2-VMM-A`  
**Status:** `IMPLEMENTATION-HARDENED / CONDITIONAL PASS`  
**Target:** x86_64, 4-level paging, UP/BSP-only

## Implemented in the current branch

The VMM validation core in `kernel/src/vmm.rs` now enforces the following fail-closed invariants before hardware page-table mutation:

- canonical x86_64 virtual addresses
- half-open userspace interval `[0x0000_0000_0001_0000, 0x0000_8000_0000_0000)`
- checked `ptr + len` arithmetic
- 4 KiB physical-frame alignment
- 48-bit physical-address baseline
- W^X (`writable && executable` is rejected)
- user mappings only inside the exact userspace interval
- HHDM restricted to supervisor/RW/NX policy
- level-specific x86 bit-7 semantics
- bounded bootstrap physical-to-virtual translation

## Page-table level semantics

The implementation treats bit 7 according to the actual x86-64 page-table level:

| Level | Bit 7 |
|---|---|
| PML4 | not PS |
| PDPT | PS (1 GiB huge page) |
| PD | PS (2 MiB huge page) |
| PT | PAT |

M1.2 baseline does not support huge pages. Therefore PS is rejected at PDPT and PD only. Bit 7 at PT is not interpreted as PS.

## Userspace policy

A mapping carrying the User bit is valid only when its virtual address is inside:

```text
[USER_SPACE_BASE, USER_SPACE_TOP_EXCLUSIVE)
```

Checking only `virt < HHDM_BASE` is insufficient because other supervisor/kernel virtual ranges may exist below the HHDM window.

## HHDM policy

The HHDM window is:

```text
[HHDM_BASE, HHDM_END)
```

HHDM entries must be:

- Present
- Writable
- Supervisor-only (`User=0`)
- NX

HHDM is therefore not a userspace mapping and is never executable.

## Current scope boundary

This commit implements the deterministic validation/policy layer. It does **not** claim completed hardware page-table programming.

The following remain explicit follow-up work before M1.2 Final Freeze:

1. integrate the validation layer with the real PML4 → PDPT → PD → PT hardware mapping path;
2. make intermediate page-table allocation transactional, rolling back newly allocated levels if a later allocation or mapping step fails;
3. integrate page-table/frame lifetime with the M1.3 kernel-object and mapping-reference model;
4. validate the complete acceptance matrix on CI and perform the final conformance audit.

## Acceptance coverage added

The regression tests cover:

- lower and upper userspace boundaries
- exact `ptr + len == TOP` acceptance
- upper-bound overflow/rejection
- kernel-high-half rejection for user mappings
- W^X rejection
- 48-bit physical-address limit
- invalid physical alignment
- level-specific PS semantics
- HHDM RW/NX/supervisor policy
- bootstrap translation containment and arithmetic overflow

## Freeze rule

`IMPLEMENTATION-HARDENED / CONDITIONAL PASS` is not equivalent to `FINAL` or `ACCEPTED`.

M1.2 may only be frozen after implementation, CI evidence, security audit, conformance evidence, and documentation are all consistent.
